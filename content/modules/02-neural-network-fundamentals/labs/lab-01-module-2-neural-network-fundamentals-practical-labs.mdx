## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---------|----------------|-----|
| **`ModuleNotFoundError: No module named 'tensorflow'`** | TensorFlow not installed in the active Python environment or virtual environment. | Run `pip install tensorflow` in the same environment where you launch the notebook. Check with `which python` / `where python`. |
| **TF 1.x behavior** | Some systems have TF 1.x installed alongside TF 2.x, or an older system package takes precedence. | Verify with `python -c "import tensorflow as tf; print(tf.__version__)"`. If 1.x, upgrade: `pip install --upgrade tensorflow`. |
| **Non-reproducible results across runs despite setting seeds** | `tf.random.set_seed(42)` sets the global TF seed, but GPU operations can still be non-deterministic. Some GPU kernels use atomic operations that have race conditions. | Add `tf.config.experimental.enable_op_determinism()` (TF 2.9+) for fully reproducible GPU runs. Note: this may reduce performance. |
| **`output/` directory permission error** | On some shared lab systems, the working directory is read-only. `os.makedirs()` raises `PermissionError`. | Use `os.makedirs("/tmp/tf_lab_output", exist_ok=True)` as a fallback and update all `plt.savefig()` calls to use the new path. |
| **Import order issues between numpy and TensorFlow** | Importing `numpy` after `tensorflow` in some versions can cause namespace conflicts or degraded performance due to TF's internal numpy replacement. | Always import `tensorflow` first, then `numpy`, then all other libraries. |
