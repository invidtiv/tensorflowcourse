# Module 3: Convolutional Neural Networks - Practical Labs

Module 3 builds CNN intuition from the ground up: you start by implementing the convolution operation in pure NumPy (including backpropagation), then assemble classic and modern architectures (LeNet-5, ResNet), benchmark them against each other, and finally learn to *understand* what a trained network has learned through filter and feature-map visualization, Grad-CAM, and layerwise activation analysis. The second half of the module covers transfer learning (VGG16, ResNet50, EfficientNet) and data augmentation pipelines — the two techniques that matter most when training on small real-world datasets.

## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---|---|---|
| `ValueError` on `to_categorical` with shape `(N, 1)` | `y_train` from `cifar10.load_data()` is shape `(50000, 1)` by default, not `(50000,)` | Flatten first: `y_train.flatten()` before passing to `to_categorical` |
| Pixel values outside `[0, 1]` for later labs | Normalization done once then overwritten when reloading data in a new cell | Store normalized arrays as `x_train_norm`/`x_test_norm` or reload and normalize every time |
| Transfer learning labs timeout on CPU | VGG16/ResNet50 feature extraction loops take 30–60 min on CPU without GPU | Use `tf.keras.applications` with `include_top=False` and cache bottleneck features to `.npy` files |
| `ImportError: tensorflow_addons` for lab-15 | `tfa` is not installed in the default TF environment | Run `pip install tensorflow-addons` before lab-15, or use `tf.image` equivalents |
| Shape mismatch when mixing MNIST and CIFAR-10 scaffolds | LeNet-5 labs use MNIST (28×28 grayscale); CIFAR-10 labs use 32×32 RGB — configs are not interchangeable | Always check `input_shape` in `model.build()` matches the dataset being used |

## Stretch Goals

1. **Profile the full module pipeline end-to-end** — time how long each lab takes on your hardware (CPU vs GPU). Build a table: lab name, dataset, #params, training time per epoch, final test accuracy. This gives you a concrete sense of the cost of each architectural choice before writing a single line of production code.
2. **Build a shared `ModelRegistry` class** — implement a lightweight dictionary that maps architecture names (`"lenet"`, `"resnet20"`, `"vgg16_ft"`) to `tf.keras.Model` factories. Every lab in the module can then register its model, allowing you to run cross-lab accuracy comparisons with a single loop.
3. **Automate the EO validation suite** — wrap each lab's assertion block into a `pytest` fixture that re-runs automatically when you change a hyperparameter. This turns the module into a regression harness: if a refactor breaks >2% accuracy on any lab, the test suite catches it immediately.
4. **Extend to CIFAR-100 throughout** — swap `cifar10` for `cifar100` in every lab and track how each technique (ResNet blocks, transfer learning, augmentation) scales to a 100-class problem. Compare the accuracy-drop ratio across labs to understand which techniques are most sensitive to class count.
