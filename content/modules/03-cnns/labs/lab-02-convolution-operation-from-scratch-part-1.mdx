# Convolution Operation from Scratch - Part 1

## Objectives
- Understand the mathematical foundation of convolution
- Implement 2D convolution using NumPy
- Visualize how kernels extract features from images

## Prerequisites
- NumPy basics
- Understanding of image representation (height, width, channels)

## Theory

The 2D convolution operation is defined as:

```
(I * K)(i, j) = Σ_m Σ_n I(i+m, j+n) × K(m, n)
```

Where:
- I is the input image
- K is the kernel/filter
- (i, j) are the output coordinates

def conv2d_single_channel(image, kernel, stride=1, padding=0):
    """
    Perform 2D convolution on a single-channel image.
    
    Args:
        image: 2D numpy array (H, W)
        kernel: 2D numpy array (kH, kW)
        stride: Step size for sliding window
        padding: Number of pixels to pad around the image
    
    Returns:
        output: 2D numpy array after convolution
    """
    # Add padding if specified
    if padding > 0:
        image = np.pad(image, padding, mode='constant', constant_values=0)
    
    # Get dimensions
    img_h, img_w = image.shape
    kernel_h, kernel_w = kernel.shape
    
    # Calculate output dimensions
    # Formula: output_size = floor((input_size + 2*padding - kernel_size) / stride) + 1
    out_h = (img_h - kernel_h) // stride + 1
    out_w = (img_w - kernel_w) // stride + 1
    
    # Initialize output
    output = np.zeros((out_h, out_w))
    
    # Perform convolution
    for i in range(out_h):
        for j in range(out_w):
            # Extract the region of interest
            i_start = i * stride
            j_start = j * stride
            region = image[i_start:i_start + kernel_h, 
                          j_start:j_start + kernel_w]
            
            # Element-wise multiplication and sum
            output[i, j] = np.sum(region * kernel)
    
    return output

def conv2d_multi_channel(image, kernels, stride=1, padding=0):
    """
    Perform 2D convolution on multi-channel image with multiple filters.
    
    Args:
        image: 3D numpy array (H, W, C_in)
        kernels: 4D numpy array (kH, kW, C_in, C_out)
        stride: Step size
        padding: Padding size
    
    Returns:
        output: 3D numpy array (H_out, W_out, C_out)
    """
    if padding > 0:
        image = np.pad(image, ((padding, padding), (padding, padding), (0, 0)), 
                      mode='constant', constant_values=0)
    
    img_h, img_w, img_c = image.shape
    kernel_h, kernel_w, kernel_c_in, kernel_c_out = kernels.shape
    
    assert img_c == kernel_c_in, "Input channels must match kernel input channels"
    
    out_h = (img_h - kernel_h) // stride + 1
    out_w = (img_w - kernel_w) // stride + 1
    
    output = np.zeros((out_h, out_w, kernel_c_out))
    
    # For each output channel
    for out_c in range(kernel_c_out):
        # For each spatial position
        for i in range(out_h):
            for j in range(out_w):
                i_start = i * stride
                j_start = j * stride
                region = image[i_start:i_start + kernel_h, 
                              j_start:j_start + kernel_w, :]
                
                # Sum over all input channels
                output[i, j, out_c] = np.sum(region * kernels[:, :, :, out_c])
    
    return output

def average_pooling(image, pool_size=2, stride=2):
    """Exercise 1 Solution: Average Pooling"""
    img_h, img_w = image.shape
    out_h = (img_h - pool_size) // stride + 1
    out_w = (img_w - pool_size) // stride + 1
    
    output = np.zeros((out_h, out_w))
    
    for i in range(out_h):
        for j in range(out_w):
            i_start = i * stride
            j_start = j * stride
            region = image[i_start:i_start + pool_size, 
                          j_start:j_start + pool_size]
            output[i, j] = np.mean(region)
    
    return output

## Common Pitfalls

- **Output shape off-by-one.** The output dimension for a `valid`
  convolution is `(H - K) // S + 1`, *not* `(H - K) / S`. Forgetting the
  `+ 1` gives outputs that are one row/column too small and silently
  corrupts downstream shape assumptions.
- **Kernel flipping.** True mathematical convolution flips the kernel;
  deep-learning "convolution" is actually cross-correlation (no flip).
  This lab uses the cross-correlation convention — do not add a
  `kernel[::-1, ::-1]` flip or your edge-detector signs will invert.
- **Integer vs float dtype.** If your test image is `dtype=np.uint8`,
  negative filter responses wrap around to large positive values
  (e.g., `-30` becomes `226`). Always cast to `float32` before
  convolving.
- **`same` padding with even kernels.** The `(K - 1) // 2` padding
  formula assumes an odd kernel size. For even-sized kernels you need
  asymmetric padding (one extra row on the bottom, one extra column on
  the right). Don't attempt even kernels in this lab — defer to the
  TensorFlow layer, which handles this internally.
- **Stride vs dilation confusion.** Stride skips *output* positions;
  dilation skips *input* positions inside the kernel. They are not
  interchangeable and produce different output shapes.
