# Module 6: Object Detection Systems - Practical Labs

## Overview

This module walks through the full object detection pipeline — from raw pixels to evaluated mAP scores — using TensorFlow 2.x. Each lab builds on the previous one, following the architecture stack that underpins modern detectors like YOLOv8 and EfficientDet:

```
Image → Backbone (FPN) → Anchor Generation → Box Regression + Classification
      → NMS Post-Processing → mAP Evaluation
```

The twelve labs below map to five conceptual stages:

1. **IoU Metrics (Labs 2–3)** — foundation for box matching, loss functions, and NMS scoring
2. **Anchor Design (Labs 4–5)** — multi-scale anchor generation and FPN-level assignment
3. **NMS Variants (Labs 6–7)** — suppressing duplicate detections at inference
4. **YOLO End-to-End (Labs 8–10)** — head architecture, training, and post-processing
5. **TF OD API (Labs 11–13)** — production pipeline, custom training, and mAP evaluation

## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---|---|---|
| Anchor units mismatch (pixel vs. normalised) | TF OD API normalises boxes to [0, 1]; YOLO uses pixel coords | Pick one coordinate space for the whole pipeline and convert at the boundary |
| `# TODO` stubs left in production code | Scaffold was treated as final | Replace every `# TODO` section with real implementations before evaluation |
| NMS threshold set too low (< 0.3) | Suppresses correct detections of adjacent objects (e.g. crowd scenes) | Use 0.45–0.5 for standard evaluation; tune per dataset |
| Grid-cell ambiguity at stride boundaries | Objects near the border of two feature-map cells get assigned to the wrong cell | Use the YOLO centroid assignment rule: assign to the cell containing the box centre |
| mAP evaluated at wrong IoU threshold | COCO uses mAP@[0.5:0.95]; Pascal VOC uses mAP@0.5 — mixing gives incomparable numbers | Always state the IoU threshold and match it to the benchmark standard |
