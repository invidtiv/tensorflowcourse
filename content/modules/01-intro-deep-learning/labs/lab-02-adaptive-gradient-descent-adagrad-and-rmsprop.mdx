def adagrad(grad_func, x_init, learning_rate=0.1, epsilon=1e-8, n_iterations=1000):
    """
    AdaGrad: Adaptive Gradient Algorithm.
    
    Update rule:
        cache_t = cache_{t-1} + gradient^2
        x_t = x_{t-1} - learning_rate * gradient / (sqrt(cache_t) + epsilon)
    """
    x = x_init.copy() if isinstance(x_init, np.ndarray) else x_init
    cache = np.zeros_like(x) if isinstance(x, np.ndarray) else 0
    
    history = [x.copy() if isinstance(x, np.ndarray) else x]
    
    for i in range(n_iterations):
        gradient = grad_func(x)
        cache = cache + gradient ** 2
        x = x - learning_rate * gradient / (np.sqrt(cache) + epsilon)
        history.append(x.copy() if isinstance(x, np.ndarray) else x)
    
    return x, history

def rmsprop(grad_func, x_init, learning_rate=0.001, decay_rate=0.9, 
            epsilon=1e-8, n_iterations=1000):
    """
    RMSprop: Root Mean Square Propagation.
    
    Update rule:
        cache_t = decay_rate * cache_{t-1} + (1 - decay_rate) * gradient^2
        x_t = x_{t-1} - learning_rate * gradient / (sqrt(cache_t) + epsilon)
    """
    x = x_init.copy() if isinstance(x_init, np.ndarray) else x_init
    cache = np.zeros_like(x) if isinstance(x, np.ndarray) else 0
    
    history = [x.copy() if isinstance(x, np.ndarray) else x]
    
    for i in range(n_iterations):
        gradient = grad_func(x)
        cache = decay_rate * cache + (1 - decay_rate) * gradient ** 2
        x = x - learning_rate * gradient / (np.sqrt(cache) + epsilon)
        history.append(x.copy() if isinstance(x, np.ndarray) else x)
    
    return x, history

def adam(grad_func, x_init, learning_rate=0.001, beta1=0.9, beta2=0.999,
         epsilon=1e-8, n_iterations=1000):
    """
    Adam: Adaptive Moment Estimation.
    
    Combines momentum with adaptive learning rates.
    """
    x = x_init.copy() if isinstance(x_init, np.ndarray) else x_init
    m = np.zeros_like(x) if isinstance(x, np.ndarray) else 0  # First moment
    v = np.zeros_like(x) if isinstance(x, np.ndarray) else 0  # Second moment
    
    history = [x.copy() if isinstance(x, np.ndarray) else x]
    
    for t in range(1, n_iterations + 1):
        gradient = grad_func(x)
        
        # Update biased first moment estimate
        m = beta1 * m + (1 - beta1) * gradient
        # Update biased second raw moment estimate
        v = beta2 * v + (1 - beta2) * gradient ** 2
        
        # Bias correction
        m_hat = m / (1 - beta1 ** t)
        v_hat = v / (1 - beta2 ** t)
        
        # Update parameters
        x = x - learning_rate * m_hat / (np.sqrt(v_hat) + epsilon)
        history.append(x.copy() if isinstance(x, np.ndarray) else x)
    
    return x, history

## Expected Output

After running the full comparison on the default 2D convex test problem
(quadratic bowl with mild anisotropy, `lr=0.1`, 200 iterations, same
initialization `w₀ = [-4, -4]` for all optimizers), you should see:

**Final loss (lower is better):**

| Optimizer | Final loss (order of magnitude) | Notes |
|-----------|----------------------------------|-------|
| Vanilla GD | `1e-2 … 1e-1` | Slow along the ill-conditioned axis — visible zig-zag in the trajectory plot. |
| AdaGrad | `1e-3 … 1e-2` | Faster than vanilla early, then stalls as the cache accumulates. |
| RMSProp | `1e-5 … 1e-4` | Smooth monotone decrease, no stalling. |
| Adam | `1e-6 … 1e-5` | Fastest and smoothest. Bias correction matters most in the first ~10 steps. |

**Trajectory plot:** vanilla GD traces the classic zig-zag across the narrow
valley; AdaGrad takes large early steps that shrink rapidly; RMSProp and Adam
produce near-straight paths to the minimum.

**Cache magnitudes at convergence:**

- `adagrad_cache.max()` grows unboundedly — typically `10²–10³` after 200 steps.
- `rmsprop_cache.max()` stays bounded, usually `< 10×` the AdaGrad initial cache
  due to the exponential moving average (`ρ=0.9` default).

**Timing (single CPU core, numpy reference implementation):**
~0.05 s per 200-step run for each optimizer. If a run takes `> 1 s`,
check for accidental Python-level loops inside the update step — all
operations should be vectorized over the parameter vector.

If your Adam curve is noticeably worse than RMSProp, the bias-correction
terms `m̂`, `v̂` are almost certainly missing — this is the single most
common bug when re-implementing Adam from scratch.

## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---------|----------------|-----|
| **AdaGrad learning rate decays to zero** | The denominator accumulates squared gradients indefinitely, so the effective learning rate shrinks monotonically. After many steps the updates become vanishingly small. | Switch to RMSProp or Adam, which use an exponential moving average instead of an unbounded sum. If you must use AdaGrad, increase the initial learning rate. |
| **Epsilon set too large** | Beginners sometimes set ε = 0.1 or 1.0 to "stabilize" AdaGrad/RMSProp. This dominates the denominator and neutralizes the adaptive behavior entirely. | Keep ε ≈ 1e-7 to 1e-8 (default in TF/PyTorch). Its only purpose is to prevent division by zero. |
| **Adam's bias correction ignored** | Implementing Adam from scratch but forgetting the bias-correction terms `m̂ = m/(1-β₁ᵗ)` and `v̂ = v/(1-β₂ᵗ)`. Early updates are heavily biased toward zero because m and v are initialized to zero. | Always apply bias correction, especially in the first ~10 steps where the bias is largest. Compare your loss curve against `tf.keras.optimizers.Adam` to catch the bug. |
| **Comparing optimizers at different learning rates** | Running vanilla GD at lr=0.01 and Adam at lr=0.01 and concluding "Adam is always better." Adam's effective per-parameter rate is lr / √v̂, so the same nominal lr means very different step sizes. | For fair comparison, tune each optimizer's learning rate independently. Use a learning rate sweep or the LR range test (Smith, 2017). |
| **Confusing RMSProp's decay rate with momentum** | RMSProp's `ρ` (or `decay`) controls the moving average of squared gradients, NOT a momentum term. Mixing them up leads to wrong hyperparameter settings. | Use `ρ ∈ [0.9, 0.999]` for the cache decay and add momentum separately if needed (TF's `tf.keras.optimizers.RMSprop` has a distinct `momentum` parameter). |
