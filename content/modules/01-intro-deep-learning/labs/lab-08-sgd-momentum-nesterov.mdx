## Objective

scratch, then compare them head-to-head against vanilla SGD on an ill-
conditioned quadratic bowl. You'll see *why* momentum matters: it damps
oscillations in steep directions and accelerates in flat ones.

## Prerequisites

- Lab 01 (vanilla GD) and Lab 07 (first TF model).
- Comfortable reading the gradient-descent update rule.

## Background

**Vanilla SGD:**

$$ \theta_{t+1} = \theta_t - \eta\,\nabla f(\theta_t) $$

**Classical momentum** (Polyak, 1964) adds a velocity buffer that is an
exponentially weighted moving average of past gradients:

$$
v_{t+1} = \beta\,v_t + \nabla f(\theta_t), \qquad
\theta_{t+1} = \theta_t - \eta\,v_{t+1}
$$

**Nesterov accelerated gradient** peeks ahead before computing the gradient:

$$
v_{t+1} = \beta\,v_t + \nabla f(\theta_t - \eta\beta v_t), \qquad
\theta_{t+1} = \theta_t - \eta\,v_{t+1}
$$

Typical `β` is 0.9. Intuitively: ordinary momentum is a ball rolling downhill
accumulating velocity; NAG is a slightly smarter ball that looks where it's
heading before stepping.

## The test problem: an ill-conditioned quadratic

```python
import numpy as np
import matplotlib.pyplot as plt

# Long, thin valley: condition number = 100
A = np.diag([1.0, 100.0])
def f(x):   return 0.5 * x @ A @ x
def grad(x): return A @ x

x0 = np.array([100.0, 1.0])   # start far along the flat axis
```

A pure gradient-descent trajectory will zig-zag violently across the steep
`y`-axis while crawling along the flat `x`-axis. This is the textbook case
where momentum shines.

## Part 1 — Implement the three optimisers

```python
def run_sgd(lr=0.015, steps=200):
    x = x0.copy(); hist = [x.copy()]
    for _ in range(steps):
        x = x - lr * grad(x)
        hist.append(x.copy())
    return np.array(hist)

def run_momentum(lr=0.015, beta=0.9, steps=200):
    x = x0.copy(); v = np.zeros_like(x); hist = [x.copy()]
    for _ in range(steps):
        v = beta * v + grad(x)
        x = x - lr * v
        hist.append(x.copy())
    return np.array(hist)

def run_nesterov(lr=0.015, beta=0.9, steps=200):
    x = x0.copy(); v = np.zeros_like(x); hist = [x.copy()]
    for _ in range(steps):
        lookahead = x - lr * beta * v
        v = beta * v + grad(lookahead)
        x = x - lr * v
        hist.append(x.copy())
    return np.array(hist)

traj_sgd = run_sgd()
traj_mom = run_momentum()
traj_nag = run_nesterov()
```

## Part 4 — Use TensorFlow's built-in optimisers

Confirm that the hand-rolled versions agree with `tf.keras.optimizers.SGD`:

```python
import tensorflow as tf

def run_tf(momentum=0.0, nesterov=False, steps=200, lr=0.015):
    x = tf.Variable(x0.astype(np.float32))
    opt = tf.keras.optimizers.SGD(learning_rate=lr,
                                  momentum=momentum,
                                  nesterov=nesterov)
    hist = [x.numpy().copy()]
    for _ in range(steps):
        with tf.GradientTape() as tape:
            loss = 0.5 * tf.tensordot(x, tf.constant(A, dtype=tf.float32) @ x, 1)
        g = tape.gradient(loss, [x])
        opt.apply_gradients(zip(g, [x]))
        hist.append(x.numpy().copy())
    return np.array(hist)

tf_sgd = run_tf()
tf_mom = run_tf(momentum=0.9)
tf_nag = run_tf(momentum=0.9, nesterov=True)
```

<Callout type="tip" title="Diagnostic tree — if something looks wrong">

1. **SGD diverges immediately** → `lr=0.015` is near the stability limit for condition number 100. If you accidentally used `lr=0.02`, expect divergence. The theoretical stability bound for this quadratic is `lr < 2 / 100 = 0.02`, so `0.015` has a small margin.
2. **Momentum trajectory identical to SGD** → Check that you initialised `v = np.zeros_like(x)` outside the loop, not inside. Reinitialising `v` every step effectively zeroes the momentum.
3. **TF NAG curve doesn't match manual NAG** → TF's `nesterov=True` in `SGD` uses a slightly different formulation (it evaluates the gradient at `θ + β²v + (1+β)∇f` to match Sutskever et al. 2013). The convergence behaviour is equivalent but trajectories may differ by a half-step offset.
4. **Momentum overshoots and diverges at β=0.99** → This is expected. The effective step size grows as `1/(1-β)`, so `β=0.99` multiplies the learning rate by ~100×, pushing it well past the stability threshold. This is a known failure mode covered in Exercise 1.

</Callout>

## Common Pitfalls

1. **Momentum coefficient `β` vs. `(1-β)` convention** — Some textbooks define the velocity update as `v = β v + (1-β) ∇f` (the "EMA" form), others use `v = β v + ∇f` (the "accumulate" form used in this lab). TF's `SGD(momentum=β)` uses the accumulate form. If you mix conventions, your effective step size will be off by `(1-β)`.
2. **In-place mutation of `x`** — If you write `x -= lr * v` (in-place) and `x` is a NumPy array, the update is correct. But if you then log `hist.append(x)` without `.copy()`, every entry in `hist` will point to the same array and all will show the final value. Always `hist.append(x.copy())`.
3. **Nesterov look-ahead direction** — The look-ahead position is `θ - η β v`, not `θ - η v`. The missing `β` factor is a common transcription error from the formula. You're peeking at where momentum would take you, which requires scaling by `β`.
4. **Condition number mismatch** — If you change `A = np.diag([1.0, 100.0])` but forget to regenerate `x0`, the starting point may no longer be in the "hard" quadrant. Always regenerate both together.

## Key takeaways

- On ill-conditioned problems, vanilla SGD oscillates across the steep
  direction and crawls along the flat one. Momentum fixes both.
- Nesterov's "look-ahead" usually gives a small edge over classical
  momentum, especially near the optimum where it reduces overshoot.
- `tf.keras.optimizers.SGD(momentum=0.9, nesterov=True)` is exactly what you
  just implemented — and it's a one-liner.
- The same principle underlies Adam, RMSprop, and every other modern
  optimiser: they are all, at heart, smarter ways of averaging past
  gradients.
