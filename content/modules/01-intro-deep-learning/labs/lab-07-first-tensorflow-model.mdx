## Background

Linear regression fits a line `y = w * x + b` to a set of points by minimising
the mean squared error (MSE):

$$
\mathcal{L}(w, b) = \frac{1}{N}\sum_{i=1}^{N}\bigl(y_i - (w x_i + b)\bigr)^2
$$

The gradients are:

$$
\frac{\partial \mathcal{L}}{\partial w} = -\frac{2}{N}\sum x_i (y_i - \hat y_i),
\quad
\frac{\partial \mathcal{L}}{\partial b} = -\frac{2}{N}\sum (y_i - \hat y_i)
$$

In TensorFlow we don't have to compute those by hand — `tf.GradientTape` does
it for us.

## Part 1 — Manual training loop with `tf.GradientTape`

```python
import numpy as np
import tensorflow as tf
import matplotlib.pyplot as plt

# 1. Synthetic data: y = 3x + 2 + noise
np.random.seed(42)
X = np.linspace(-1, 1, 200).astype(np.float32)
y = 3.0 * X + 2.0 + np.random.normal(0, 0.3, size=X.shape).astype(np.float32)

# 2. Trainable parameters
w = tf.Variable(0.0, name="w")
b = tf.Variable(0.0, name="b")

# 3. Hyperparameters
lr = 0.1
epochs = 200
history = []

# 4. Training loop
for epoch in range(epochs):
    with tf.GradientTape() as tape:
        y_pred = w * X + b
        loss = tf.reduce_mean((y - y_pred) ** 2)
    grads = tape.gradient(loss, [w, b])
    w.assign_sub(lr * grads[0])
    b.assign_sub(lr * grads[1])
    history.append(loss.numpy())
    if epoch % 20 == 0:
        print(f"epoch {epoch:3d}  loss={loss.numpy():.4f}  w={w.numpy():.3f}  b={b.numpy():.3f}")

print(f"\nFinal: w={w.numpy():.3f}, b={b.numpy():.3f} (target w=3, b=2)")
```

### What to observe

- Loss should drop from ~4 to under 0.1 within ~100 epochs.
- `w` and `b` converge close to the true values (3 and 2).
- `tf.GradientTape` automatically derives the gradients — you never had to
  write `-2/N * sum(...)` yourself.

## Part 2 — The Keras equivalent

```python
model = tf.keras.Sequential([
    tf.keras.layers.Dense(1, input_shape=(1,), use_bias=True)
])
model.compile(optimizer=tf.keras.optimizers.SGD(learning_rate=0.1),
              loss="mse")
model.fit(X, y, epochs=200, verbose=0)

w_keras, b_keras = model.layers[0].get_weights()
print("Keras w:", w_keras.flatten(), "b:", b_keras)
```

Both approaches should converge to essentially the same `(w, b)`. The Keras
version is ~5 lines; the manual loop is ~15. But now you know exactly what
`model.fit` is doing behind the scenes.

## Part 3 — Plot the loss curve and the learned line

```python
fig, axes = plt.subplots(1, 2, figsize=(11, 4))
axes[0].plot(history)
axes[0].set_title("Training loss (manual loop)")
axes[0].set_xlabel("epoch"); axes[0].set_ylabel("MSE")

axes[1].scatter(X, y, s=12, alpha=0.6, label="data")
xs = np.linspace(-1, 1, 100)
axes[1].plot(xs, w.numpy() * xs + b.numpy(), "r-", lw=2, label="learned")
axes[1].set_title("Fit")
axes[1].legend()
plt.tight_layout(); plt.show()
```

## Key takeaways

- `tf.Variable` holds trainable state; `tf.GradientTape` records operations
  and computes gradients automatically.
- `tf.keras.Sequential` + `model.compile` + `model.fit` is a thin wrapper
  around that same loop.
- Even a one-neuron Dense layer is a legitimate neural network — you just
  built one.

<Callout type="tip" title="Diagnostic tree — if something looks wrong">

1. **`w` stuck near 0 after 200 epochs** → Check that you used `w.assign_sub(lr * grads[0])`, not `w = w - lr * grads[0]` (which creates a new tensor rather than updating the `tf.Variable` in-place).
2. **Loss oscillates and never settles** → Your learning rate is too large. Try `lr = 0.01`. The stability threshold for this problem is roughly `lr < 2 / (N * max_eigenvalue_of_X^T X)`.
3. **Keras `w` very different from manual `w` (>0.5 difference)** → Confirm both runs use `lr=0.1`, `epochs=200`, and the same `np.random.seed(42)` data. The Keras optimizer shuffles internally — add `shuffle=False` to `model.fit` to get a tighter match.
4. **`assert abs(w.numpy() - 3.0) < 0.2` fails** → Your `w` didn't converge — recheck the gradient sign. The update is `w -= lr * dL/dw`; a missing minus sign gives gradient ascent, not descent.

</Callout>

## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---|---|---|
| `tape.gradient(loss, [w, b])` returns `[None, None]` | `w` and `b` were created with `tf.constant` instead of `tf.Variable`; GradientTape only tracks `tf.Variable` by default | Replace `tf.constant(0.0)` with `tf.Variable(0.0)` for every trainable parameter |
| Loss stays flat at its initial value after many epochs | The `assign_sub` step is missing or the learning rate is so small that updates are below float32 precision | Print `grads[0].numpy()` to confirm non-zero gradients; if `None`, see row above; if near zero, raise `lr` to 0.1 |
| `y_pred` has shape `(200, 200)` instead of `(200,)` | `X` was accidentally reshaped to `(200, 1)`, and `w * X` broadcasts to a 2-D result | Ensure `X` has shape `(200,)` or explicitly write `y_pred = (w * X + b).numpy()` and check the shape before computing loss |
| Keras `w` differs from manual `w` by more than 0.5 | Both runs must share the same data seed, learning rate, and epoch count; Keras shuffles internally by default | Add `shuffle=False` to `model.fit(X, y, ..., shuffle=False)` for an exact match, or accept small differences from shuffling |
| `input_shape` deprecation warning in TF 2.16+ | Keras 3 deprecated the `input_shape` constructor argument to `Dense` | Use `model.build((None, 1))` after constructing the Sequential model, or add an explicit `tf.keras.layers.Input(shape=(1,))` first |

<Callout type="warning" title="Common Pitfalls">

1. **`tape.gradient` returns `None`** — You used `tf.constant` instead of
   `tf.Variable` for `w` or `b`. By default, `GradientTape` only watches
   `tf.Variable`s. Use `tape.watch(x)` to track arbitrary tensors.
2. **Loss stuck at initial value** — The variable `assign_sub` step is
   missing or the learning rate is effectively zero. Print
   `grads[0].numpy()` to confirm non-zero gradients.
3. **Shape mismatch in `y_pred = w * X + b`** — If `X` has shape `(200,)`
   and `w` is shape `()`, broadcasting works fine. But if you accidentally
   reshape `X` to `(200, 1)` you'll get a `(200, 200)` prediction. Always
   print `y_pred.shape` before computing the loss.
4. **`input_shape` deprecation in Keras 3** — In Keras 3 (shipped with
   TF 2.16+) the `input_shape` argument to the first layer is deprecated;
   use `model.build((None, 1))` after construction, or pass `shape=(1,)` to
   a leading `tf.keras.layers.Input` layer instead.

</Callout>
