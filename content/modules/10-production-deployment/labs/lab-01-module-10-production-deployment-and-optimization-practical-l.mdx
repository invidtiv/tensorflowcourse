# Module 10: Production Deployment and Optimization - Practical Labs

## Overview

This module follows the complete ML production lifecycle: you start with a trained model,
progressively optimize it for size and latency, package it for edge or cloud serving,
orchestrate the end-to-end pipeline with TFX, and finally monitor the live system for
drift and degradation.

**Deployment progression:**

1. **Optimize the model** — quantization (PTQ, QAT, float16) and pruning reduce size 4–8x
   and latency 2–4x with minimal accuracy loss.
2. **Package for edge** — TFLite conversion and mobile inference wrappers bring the model
   to Android/iOS with on-device hardware acceleration (NNAPI, CoreML, GPU delegate).
3. **Serve at scale** — TensorFlow Serving exposes a versioned REST and gRPC endpoint;
   Docker Compose adds health checks, rolling upgrades, and replica scaling.
4. **Orchestrate with TFX** — the full pipeline (ExampleGen → Transform → Trainer →
   Evaluator → Pusher) tracks artifacts in ML Metadata, enabling reproducibility and
   automated retraining.
5. **Monitor in production** — drift detection (KS test, PSI, Wasserstein) and performance
   monitoring (accuracy, latency, alert tiers) close the feedback loop.

Run each block after installing the required packages to confirm your environment is ready.

```python
# ── 1. TFLite conversion (runs in 5 seconds on any trained Keras model) ──────
import tensorflow as tf

# Save any Keras model first, then convert
model = tf.keras.applications.MobileNetV2(weights=None, input_shape=(224, 224, 3))
converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]          # dynamic-range quantization
tflite_model = converter.convert()
with open("mobilenet_quant.tflite", "wb") as f:
    f.write(tflite_model)

# Verify the converted model loads and produces the right output shape
interpreter = tf.lite.Interpreter(model_path="mobilenet_quant.tflite")
interpreter.allocate_tensors()
inp = interpreter.get_input_details()[0]
out = interpreter.get_output_details()[0]
print(f"Input : {inp['shape']} {inp['dtype']}")   # (1, 224, 224, 3) float32
print(f"Output: {out['shape']} {out['dtype']}")   # (1, 1000) float32
```

```python
# ── 3. Drift detection stub ───────────────────────────────────────────────────
import numpy as np
from scipy.stats import ks_2samp

def check_drift(reference: np.ndarray, production: np.ndarray,
                threshold: float = 0.05) -> dict:
    """Run KS test; return statistic, p-value, and drift flag."""
    stat, pval = ks_2samp(reference, production)
    return {"statistic": round(stat, 4), "pval": round(pval, 4),
            "drift_detected": pval < threshold}

# Smoke-test
ref = np.random.normal(0, 1, 1000)
prod_ok = np.random.normal(0, 1, 500)
prod_drift = np.random.normal(1.5, 1.2, 500)
print("No drift:", check_drift(ref, prod_ok))
print("Drift   :", check_drift(ref, prod_drift))
```

## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---------|---------------|-----|
| Skipping environment version pins before starting any lab | TFX, TFLite, and TF Serving have tightly coupled version requirements; mixing major versions produces cryptic proto errors at runtime | Pin `tensorflow==2.13.*`, `tfx==1.13.*`, and `tensorflow-model-optimization==0.7.*` in a dedicated virtualenv before running any lab |
| Running all labs in a single notebook without restarting the kernel | TFX registers global signal handlers and ML Metadata connections that persist across cells; a second pipeline run in the same kernel often hits "database is locked" or stale artifact errors | Use one notebook (or one Python process) per lab; restart the kernel between lab sections that use TFX |
| Benchmarking on the development machine and extrapolating to edge devices | x86 performance numbers do not translate to ARM; INT8 speedup ratios are much larger on NEON-capable ARM cores (Raspberry Pi, Android) than on x86 | Always validate latency and throughput on the actual target device or a representative ARM board |
| Building the full TFX pipeline before validating individual components | End-to-end pipeline failures produce long stack traces that are hard to debug; a broken `preprocessing_fn` is invisible until Transform runs | Validate each TFX component in isolation (Lab 11) before wiring the full pipeline (Lab 12) |
| Deploying a model without a monitoring baseline | Without a reference distribution established at deployment time, drift detection has nothing to compare against | Always capture and store the training/validation data statistics as the monitoring baseline immediately when the model is deployed, before any production traffic arrives |
