# One-Cycle Policy

```python
"""
Lab 2.3: One-Cycle Learning Rate Policy
========================================
Implement the one-cycle policy for super-convergence.
"""

import tensorflow as tf
import numpy as np
import matplotlib.pyplot as plt

class OneCyclePolicy(tf.keras.optimizers.schedules.LearningRateSchedule):
    """
    One-cycle learning rate policy.
    Combines learning rate and momentum cycling for super-convergence.
    """
    
    def __init__(self, max_lr=0.1, total_steps=10000, pct_start=0.3,
                 anneal_strategy='cos', base_momentum=0.85, max_momentum=0.95):
        super().__init__()
        self.max_lr = max_lr
        self.total_steps = total_steps
        self.pct_start = pct_start
        self.anneal_strategy = anneal_strategy
        self.base_momentum = base_momentum
        self.max_momentum = max_momentum
        
    def __call__(self, step):
        step = tf.cast(step, tf.float32)
        total_steps = tf.cast(self.total_steps, tf.float32)
        progress = step / total_steps
        
        if progress < self.pct_start:
            phase_progress = progress / self.pct_start
            if self.anneal_strategy == 'cos':
                lr = self.max_lr * (1 + tf.cos(np.pi * (1 - phase_progress))) / 2
            else:
                lr = self.max_lr * phase_progress
        else:
            phase_progress = (progress - self.pct_start) / (1 - self.pct_start)
            if self.anneal_strategy == 'cos':
                lr = self.max_lr * (1 + tf.cos(np.pi * phase_progress)) / 2
            else:
                lr = self.max_lr * (1 - phase_progress)
        
        return lr
    
    def get_momentum(self, step):
        step = tf.cast(step, tf.float32)
        total_steps = tf.cast(self.total_steps, tf.float32)
        progress = step / total_steps
        
        if progress < self.pct_start:
            phase_progress = progress / self.pct_start
            momentum = self.max_momentum - (self.max_momentum - self.base_momentum) * phase_progress
        else:
            phase_progress = (progress - self.pct_start) / (1 - self.pct_start)
            momentum = self.base_momentum + (self.max_momentum - self.base_momentum) * phase_progress
        
        return momentum
    
    def get_config(self):
        return {'max_lr': self.max_lr, 'total_steps': self.total_steps,
                'pct_start': self.pct_start, 'anneal_strategy': self.anneal_strategy,
                'base_momentum': self.base_momentum, 'max_momentum': self.max_momentum}

def visualize_one_cycle():
    total_steps = 10000
    
    policy = OneCyclePolicy(max_lr=0.1, total_steps=total_steps, pct_start=0.3,
                            anneal_strategy='cos', base_momentum=0.85, max_momentum=0.95)
    
    steps = np.arange(total_steps)
    lrs = [policy(s).numpy() for s in steps]
    momentums = [policy.get_momentum(s).numpy() for s in steps]
    
    fig, axes = plt.subplots(1, 2, figsize=(14, 5))
    
    axes[0].plot(steps, lrs, linewidth=2, color='blue')
    axes[0].set_xlabel('Training Steps'); axes[0].set_ylabel('Learning Rate')
    axes[0].set_title('One-Cycle Learning Rate', fontweight='bold')
    axes[0].grid(True, alpha=0.3)
    
    axes[1].plot(steps, momentums, linewidth=2, color='red')
    axes[1].set_xlabel('Training Steps'); axes[1].set_ylabel('Momentum')
    axes[1].set_title('One-Cycle Momentum', fontweight='bold')
    axes[1].grid(True, alpha=0.3)
    
    plt.tight_layout()
    plt.savefig('one_cycle_policy.png', dpi=150)
    plt.show()

visualize_one_cycle()
```

Visualising `OneCyclePolicy` with max_lr=0.1, total_steps=10,000, pct_start=0.3, cosine annealing, momentum ∈ [0.85, 0.95].

| Step | LR (approx) | Momentum (approx) | Phase |
|---|---|---|---|
| 0 | ~0.0 | 0.95 | Warmup start (LR rises, momentum falls) |
| 1500 | ~0.05 | 0.90 | Mid-warmup |
| 3000 | 0.10 | 0.85 | Peak LR (pct_start=0.3 × 10000) |

| 8000 | ~0.025 | 0.92 | Lower LR, higher momentum |
| 10000 | ~0.0 | 0.95 | Final annihilation phase |

LR and momentum curves should be anti-correlated throughout. The `get_config` round-trip must preserve all 6 hyperparameters.

## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---|---|---|
| Momentum cycling has no effect when using Adam | `OneCyclePolicy.get_momentum` is a standalone method; Keras optimizers do not auto-call it — momentum is only cycled if you update `optimizer.momentum` manually inside a `LambdaCallback` | Pair the policy exclusively with `SGD(momentum=...)` and update momentum at each step via `on_train_batch_begin`: `optimizer.momentum = policy.get_momentum(optimizer.iterations)` |
| LR at step 0 is exactly 0, causing NaN loss on the first batch | `pct_start=0.3` with cosine warmup computes `max_lr * (1 + cos(π×(1-0)))/2 = max_lr * 0` at step 0 | Set a floor by returning `max(lr, min_lr)` where `min_lr = max_lr / 1000`; alternatively use `anneal_strategy='linear'` which produces a small but non-zero starting LR |
| `pct_start` expressed as percentage instead of fraction | Passing `pct_start=30` instead of `pct_start=0.3` causes the warmup phase to consume 100% of training steps (30 × total_steps), making the entire schedule a warmup | Add a guard `assert 0 < pct_start < 1` in `__init__` and document the expected range (0.1–0.4 per Smith 2018) |
| Super-convergence not observed in short runs | The one-cycle policy achieves super-convergence over a single large-batch cycle; it requires training for fewer total steps than standard schedules — if total_steps is too large, the high-LR phase overshoots | Use total_steps = steps_per_epoch × num_epochs and verify that the entire dataset is seen exactly once during the cycle; do not pad total_steps |
| LR and momentum curves are identical in shape (not anti-correlated) | A bug in `get_momentum` copies the LR formula instead of inverting it; both warmup and anneal branches increase when they should mirror each other | Compare `policy(step)` and `policy.get_momentum(step)` at steps 0, pct_start×total, total; verify that when LR is at its maximum, momentum is at `base_momentum` (0.85) |
