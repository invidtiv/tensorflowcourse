# Learning Rate Finder

```python
"""
Lab 2.4: Learning Rate Finder
==============================
Automatically find optimal learning rate range.
"""

import tensorflow as tf
import numpy as np
import matplotlib.pyplot as plt

class LearningRateFinder:
    """
    Learning rate finder based on the method by Leslie Smith.
    Increases learning rate exponentially and tracks loss to find optimal range.
    """
    
    def __init__(self, model, optimizer='sgd', loss='categorical_crossentropy'):
        self.model = model
        self.optimizer_name = optimizer
        self.loss = loss
        self.lrs = []
        self.losses = []
        self.best_loss = float('inf')
        
    def find(self, x_train, y_train, start_lr=1e-7, end_lr=10, num_iter=100, batch_size=32):
        self.model = tf.keras.models.clone_model(self.model)
        
        lr_mult = (end_lr / start_lr) ** (1 / num_iter)
        lr = start_lr
        
        if self.optimizer_name == 'sgd':
            optimizer = tf.keras.optimizers.SGD(learning_rate=lr, momentum=0.9)
        else:
            optimizer = tf.keras.optimizers.Adam(learning_rate=lr)
        
        self.model.compile(optimizer=optimizer, loss=self.loss, metrics=['accuracy'])
        
        dataset = tf.data.Dataset.from_tensor_slices((x_train, y_train))
        dataset = dataset.shuffle(buffer_size=1000).batch(batch_size)
        iterator = iter(dataset)
        
        for i in range(num_iter):
            try:
                x_batch, y_batch = next(iterator)
            except StopIteration:
                iterator = iter(dataset)
                x_batch, y_batch = next(iterator)
            
            optimizer.learning_rate.assign(lr)
            
            with tf.GradientTape() as tape:
                predictions = self.model(x_batch, training=True)
                loss_value = tf.keras.losses.get(self.loss)(y_batch, predictions)
            
            gradients = tape.gradient(loss_value, self.model.trainable_variables)
            optimizer.apply_gradients(zip(gradients, self.model.trainable_variables))
            
            self.lrs.append(lr)
            self.losses.append(float(loss_value.numpy()))
            
            if loss_value > 4 * self.best_loss:
                break
            
            if loss_value < self.best_loss:
                self.best_loss = loss_value
            
            lr *= lr_mult
            
            if i % 10 == 0:
                print(f"Iteration {i}/{num_iter}, LR: {lr:.2e}, Loss: {loss_value:.4f}")
    
    def plot(self, skip_start=10, skip_end=5, save_path='lr_finder.png'):
        lrs = self.lrs[skip_start:-skip_end] if skip_end > 0 else self.lrs[skip_start:]
        losses = self.losses[skip_start:-skip_end] if skip_end > 0 else self.losses[skip_start:]
        
        plt.figure(figsize=(10, 6))
        plt.plot(lrs, losses, linewidth=2)
        plt.xscale('log')
        plt.xlabel('Learning Rate (log scale)', fontsize=12)
        plt.ylabel('Loss', fontsize=12)
        plt.title('Learning Rate Finder', fontsize=14, fontweight='bold')
        plt.grid(True, alpha=0.3)
        
        min_loss_idx = np.argmin(losses)
        suggested_lr = lrs[max(0, min_loss_idx - 5)]
        plt.axvline(suggested_lr, color='red', linestyle='--',
                   label=f'Suggested LR: {suggested_lr:.2e}')
        plt.legend()
        
        plt.savefig(save_path, dpi=150)
        plt.show()
        
        return suggested_lr

def demo_lr_finder():
    (x_train, y_train), _ = tf.keras.datasets.mnist.load_data()
    x_train = x_train[:5000].reshape(-1, 784).astype('float32') / 255.0
    y_train = tf.keras.utils.to_categorical(y_train[:5000], 10)
    
    model = tf.keras.Sequential([
        tf.keras.layers.Dense(128, activation='relu', input_shape=(784,)),
        tf.keras.layers.Dense(64, activation='relu'),
        tf.keras.layers.Dense(10, activation='softmax')
    ])
    
    lr_finder = LearningRateFinder(model, optimizer='adam')
    lr_finder.find(x_train, y_train, start_lr=1e-6, end_lr=1, num_iter=100)
    suggested_lr = lr_finder.plot()
    
    print(f"\nSuggested learning rate: {suggested_lr:.2e}")
    return suggested_lr

suggested_lr = demo_lr_finder()
```

## Expected Output

The lab implements Smith's LR range test: exponential LR sweep from 1e-7 to 10 over one epoch, recording loss at each step.

Expected signals:
- **LR-vs-loss plot** shows a characteristic V-shape on log scale: flat at very low LR → steep descent → minimum → steep rise (divergence).
- **Suggested LR** ≈ 1e-3 to 3e-3 for Adam on CIFAR-10 (one order below the divergence knee).
- For SGD, suggested LR is typically 5-10× higher (~0.01–0.03).
- If the loss curve is monotonically increasing from the start: model weights were not freshly initialized, or the LR range starts too high.
- If the curve is flat everywhere: LR range ends too low (max_lr < 1e-4), or the model has no trainable parameters (frozen backbone).

A healthy LR-finder sweep on a small conv/MLP baseline (e.g. Fashion-MNIST, ~30k steps per sweep batch) produces these characteristic signals:

- **Loss curve shape:** flat-or-slightly-decreasing in the warmup band (`1e-7 → 1e-5`), a clear **downward slope** through the "usable" band (typically `1e-4 → 1e-2`), and a sharp upward divergence after ~`1e-1`. Plotting `loss` vs `log10(lr)` should look like a shallow bathtub with the right wall going vertical.
- **Suggested LR:** `suggested_lr` usually lands in the range **`3e-4` to `3e-3`** for Adam/AdamW on small vision tasks, and **`1e-2` to `1e-1`** for SGD+momentum. If your suggestion falls outside these bands, smooth the loss harder (larger EMA window) or widen the sweep range — don't just trust the raw argmin-of-gradient.
- **Steepest-descent point:** the LR corresponding to the steepest negative gradient of the smoothed loss is typically **5–10× smaller** than the LR where loss first explodes. The One-Cycle max_lr should equal the explosion point; the "safe" constant LR should equal the steepest-descent point.
- **Downstream validation:** training at `suggested_lr` for ~5 epochs should reach **≥70% of the final accuracy you'd get at that LR trained to convergence**. If it stalls at chance, the sweep converged on a spurious local minimum — rerun with a different seed or a shorter smoothing window.
- **Wall-clock:** one full sweep (100 steps, batch 128, small model) runs in **~15–45 s on Colab T4** and **~2–5 min on CPU**. If your sweep takes >10× that, your batch size or model is too large for the probe — use a subset.

**Diagnostic tree if the curve looks wrong:**

1. **No down-slope anywhere (loss flat across all LRs):** batch size too small, smoothing window too wide, or the model has no trainable parameters in the layers you expect — verify `len(model.trainable_variables) > 0` before the sweep.
2. **Loss explodes at the *start* of the sweep:** `start_lr` is already past the stable region — drop it to `1e-8` or check that weights were reset after a previous run.
3. **Loss never explodes even at `end_lr`:** `end_lr` is too low (widen to `10`) *or* loss smoothing is masking divergence — reduce the EMA beta from 0.98 to ~0.90.
4. **Suggested LR differs by >10× between runs:** probe is too noisy — increase the batch size for the sweep, or average `suggested_lr` across 3 seeds.



<Callout type="pitfall" title="Common Pitfalls">

1. **Not resetting model weights between the sweep and the real training run.** The LR
   finder mutates `model.weights` during its probe. Either clone the model before the
   sweep (`tf.keras.models.clone_model`) or checkpoint weights with `model.get_weights()`
   and restore them after, or your "final" training starts from a half-converged state.
2. **Using `optimizer='sgd'` on a problem that actually needs Adam.** LR-finder results
   are optimizer-specific — the ideal LR for SGD is typically 10–100× larger than for
   Adam on the same model. Run the sweep with the optimizer you intend to train with.
3. **Picking the LR at the *minimum* loss instead of an order of magnitude below it.**
   The minimum is the *edge* of divergence. Smith's rule is `lr = min_loss_lr / 10`, or
   equivalently "the steepest descent point on the log-LR vs loss curve."
4. **Too few iterations (< 50) on a realistic model.** Batch-to-batch noise dominates
   the loss curve and the suggested LR becomes unstable. Use ≥ 100 iterations and
   smooth with an EMA (`beta ≈ 0.98`) before differentiating.
5. **Running the sweep on a single large batch or a non-shuffled subset.** The LR
   finder assumes each step sees a fresh mini-batch drawn from the full distribution;
   repeating the same batch collapses the implicit noise and the curve flattens.

</Callout>

## Common Pitfalls

| Pitfall | Why It Happens | Fix |
|---|---|---|
| Model weights not reset before real training | `LearningRateFinder.find()` mutates model weights during the probe sweep | Call `model.set_weights(original_weights)` after the sweep, or pass a cloned model via `tf.keras.models.clone_model(model)` |
| Picking the LR at the loss minimum | The minimum is the divergence edge, not the stable operating point | Use `suggested_lr = lr_at_min_loss / 10` or identify the steepest-negative-slope point on the smoothed curve |
| Running the sweep with the wrong optimizer | Optimal LR is optimizer-specific; SGD needs 10–100× higher LR than Adam | Always run `LearningRateFinder` with the same optimizer you will use for full training |
| Too few sweep iterations (< 50) | Batch noise dominates; curve appears jagged and argmin is unstable | Use `num_iter >= 100` with EMA smoothing (`beta=0.98`) before computing the derivative |
| Non-shuffled or repeated mini-batches in the sweep | Repeating the same batch collapses noise and flattens the loss curve artificially | Ensure the dataset is shuffled and `repeat()`-ed before feeding the finder loop |
